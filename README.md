# VK Ads MCP — hardened fork

Защищённый форк [`askads/mcp-vk-ads`](https://github.com/askads/mcp-vk-ads) для работы AI-ассистента с боевым кабинетом VK Рекламы.

Главная цель форка — сохранить готовую интеграцию с VK Ads API, но поставить серверные ограничения между моделью и реальными рекламными деньгами.

> **Важно:** не устанавливайте `mcp-vk-ads@latest`, если хотите использовать hardening из этого репозитория. Это upstream npm-пакет и в нём нет наших ограничений.

## Текущий статус

Работает:

- чтение кампаний, групп, объявлений, баланса и статистики;
- создание и изменение объектов через VK Ads API;
- центральная политика write-доступа;
- принудительное создание остановленных черновиков;
- серверные ограничения бюджета;
- жёстко закреплённый API origin;
- отключённая внешняя телеметрия;
- runtime dependency audit в CI;
- заблокированная передача `client_secret` через MCP/AI-чат.

Пока **не реализовано** безопасное постоянное хранение `client_secret` и refresh token. До этого момента для подключения используется только локально заданный `VK_ADS_TOKEN`.

## Модель безопасности

### API origin

Сервер может обращаться с VK Ads credentials только к:

```text
https://ads.vk.com/api
```

Произвольный `VK_ADS_API_BASE` запрещён. `raw_request` также не принимает абсолютные URL на другой origin.

### Write modes

Переменная `VK_ADS_WRITE_MODE` задаёт серверные права:

| Режим | Что разрешено |
|---|---|
| `read-only` | Только чтение. Это режим по умолчанию. Любые POST/DELETE блокируются до сети. |
| `draft` | Создание кампаний, групп и объявлений только со `status=blocked`, а также остановка существующих объектов. |
| `full` | Остальные write-операции, включая изменение параметров и активацию. |

Даже если AI-клиент ошибётся, ограничения применяет сам MCP-сервер.

### Budget caps

Можно физически ограничить бюджеты:

```text
VK_ADS_MAX_DAILY_BUDGET=5000
VK_ADS_MAX_TOTAL_BUDGET=30000
```

Запрос выше лимита отклоняется до обращения к VK Ads.

## Авторизация

Не отправляйте в AI-чат:

- `client_secret`;
- access token;
- refresh token.

Upstream `start_login` / `finish_login` передавал `client_secret` через аргументы MCP-инструмента. В этом форке такой flow отключён: `finish_login` не принимает credentials.

Временный безопасный вариант — получить access token вне AI-чата и передать его **только окружению локального MCP-процесса**:

```text
VK_ADS_TOKEN=<secret>
```

`auth_status` позволяет проверить факт подключения, не возвращая сам токен.

Следующий hardening-этап — local-only setup с защищённым хранилищем credentials на Windows, чтобы автоматически обновлять токен без plaintext JSON и без участия модели.

## Запуск проверенного форка

Пока форк не опубликован как отдельный пакет, используйте локальный checkout конкретного проверенного commit:

```bash
git clone https://github.com/tishin-serg/mcp-vk-ads.git
cd mcp-vk-ads
git checkout <reviewed-commit>
npm ci
npm run build
```

Далее MCP-клиент должен запускать локальный `dist/index.js`, например концептуально:

```json
{
  "command": "node",
  "args": ["/absolute/path/to/mcp-vk-ads/dist/index.js"],
  "env": {
    "VK_ADS_TOKEN": "...",
    "VK_ADS_WRITE_MODE": "read-only"
  }
}
```

Сначала подключайте кабинет только в `read-only`. После проверки чтения и статистики можно перейти к `draft`. `full` нужен только для явно контролируемых write-сценариев.

## Рабочий сценарий

Целевой процесс для AI-медиабайера:

1. ассистент читает текущий кабинет и статистику;
2. анализирует расходы, CPM/CTR/конверсии, аудитории и действующие кампании;
3. предлагает медиаплан и рекламные гипотезы;
4. в `draft` создаёт остановленные кампании/группы/объявления;
5. пользователь проверяет план;
6. запуск и изменение боевого бюджета выполняются только в разрешённом режиме и в пределах серверных caps.

## Проверки безопасности

CI запускается на Node.js 20/22/24 и проверяет:

- runtime dependency audit (`npm audit --omit=dev --audit-level=high`);
- TypeScript typecheck;
- build;
- полный набор тестов.

Отдельные тесты проверяют, что:

- `read-only` блокирует запись до сети;
- `draft` принудительно создаёт объекты остановленными;
- stop в `draft` разрешён только для известных advertising endpoints;
- delete запрещён вне `full`;
- budget caps нельзя обойти обычными typed tools или `raw_request`;
- телеметрия не делает сетевых запросов;
- `client_secret` не принимается MCP auth tools;
- API origin нельзя перенаправить на чужой сервер.

Подробнее: [`docs/HARDENING.md`](./docs/HARDENING.md).
