# VK Реклама: Статистика — MCP-инструмент (tool)

**MCP-инструмент (tool) для VK Рекламы:** Возвращает статистику по кампаниям (ad_plans), группам объявлений (ad_groups) или объявлениям (banners) из сервиса статистики VK Рекламы v3.

Техническое имя: `get_statistics`

## Какую задачу решает

> Я хочу посмотреть статистику.

Возвращает статистику по кампаниям (ad_plans), группам объявлений (ad_groups) или объявлениям (banners) из сервиса статистики VK Рекламы v3.

## Когда использовать

Используйте эту возможность, когда нужен результат «Статистика» без ручной работы в интерфейсе VK Рекламы. Операция выполняется только по вызову из AI-приложения.

## Что нужно передать

- `entity` — **необязательно**. Тип объектов для отчёта. По умолчанию banners.
- `period` — **необязательно**. `summary` (по умолчанию) — сводка за выбранные даты; `day` — дневные строки. `week/month` не поддерживаются.
- `ids` — **необязательно**. Ограничить отчёт этими id объектов (выбранного entity).
- `dateFrom` — **обязательно**. Дата начала, YYYY-MM-DD, в том числе для summary.
- `dateTo` — **обязательно**. Дата окончания, YYYY-MM-DD, не раньше dateFrom.
- `metrics` — **необязательно**. Группы метрик в отчёте, например base, events, video. По умолчанию — набор API.
- `sortBy` — **необязательно, только summary**. Поле сортировки на стороне сервера, например base.spent / base.clicks / base.shows (топ-N по метрике).
- `order` — **необязательно, только summary**. Направление сортировки для sortBy.
- `limit` — **необязательно, только summary**. Сколько объектов на страницу (не больше 250).
- `offset` — **необязательно, только summary**. Смещение постраничной выдачи.
- `autoPaginate` — **необязательно, только summary**. Забрать все страницы по offset/count.

## Что вернёт

Возвращает статистику по кампаниям (ad_plans), группам объявлений (ad_groups) или объявлениям (banners) из сервиса статистики VK Рекламы v3.

## Что изменится в VK Рекламе

Инструмент только читает данные или состояние подключения и не изменяет их.

## Пример запроса

> Посмотреть статистику в VK Рекламе. Если не хватает обязательных идентификаторов, сначала уточни их.

## Возможные ошибки и ограничения

`summary` использует `v3/statistics/{entity}/day.json`: несмотря на имя URL,
он возвращает `items[].total.base` за заданные даты, с пагинацией и сортировкой.
Группы метрик передаются через `fields`. Верхний `total.base` относится только к
возвращённым объектам страницы (`_totalScope=returned-items`); spent — в валюте
кабинета. При autoPaginate этот page total опускается (`_totalScope=not-provided`),
чтобы итог первой страницы не выглядел итогом всего кабинета. Анализируйте
`items[].total`; производные CPM/CPC/CTR нельзя складывать.

`day` использует `v2/statistics/{entity}/day.json`: группы метрик через `metrics`,
дневные данные в `items[].rows[].base`. Этот endpoint не поддерживает параметры
пагинации и сортировки инструмента: они отклоняются до запроса, а не игнорируются.
Для недели/месяца получите day и агрегируйте строки отдельно.

Путь v3 `/summary.json` не используется: на живом API он возвращал 404.
v2 `/summary.json` также не используется как замена диапазонной сводки, чтобы
не выдать показатели за всё время вместо явно выбранных дат.

Доступ также зависит от прав токена, квот и ограничений исходного API.
